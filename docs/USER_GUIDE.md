## Что это такое

**Company News Monitor** — локальная система для автоматического поиска упоминаний компаний в российских новостях. Работает полностью на вашем компьютере, **не требует установки серверов** и использует только бесплатные API и открытые данные.

### Что она умеет

- Автоматически строит ключевую базу из списка компаний (название + ИНН)
- Извлекает ФИО директоров через DaData API
- Находит связанные компании через анализ адресов в ФСРАР Open Data
- Парсит **41 источник** новостей (федеральные + региональные + отраслевые)
- Фильтрует результаты по приоритетам **H / M / L**
- Убирает дубликаты между запусками через кэш URL

### Что она НЕ умеет

- ❌ Обходить блокировки Google News / Yandex News
- ❌ Работать на Linux / macOS (только Windows)
- ❌ Парсить закрытые Telegram-каналы
- ❌ Искать в архивах старше 7 дней (RSS отдаёт только последние)

## Три режима работы

| Режим | Кнопка | Когда | Время | Что делает |
|---|---|---|---|---|
| **1. Настройка** | `НАСТРОЙКА.bat` | При смене списка компаний | 10–15 мин | Строит ключевую базу |

## Режим 1: НАСТРОЙКА

Запускается **при первом использовании** и при смене списка компаний. Состоит из 5 шагов.

```text
[Excel] → [DaData] → [DaData Aff] → [Expand] → [Merge] → keywords_all.csv
```

### Предварительные требования

1. `_config\counterparties.xlsx` — Excel со списком компаний:
   - Столбец A: `Наименование`
   - Столбец B: `ИНН` (10 или 12 цифр, **обязательно текстом!**)
2. `_bin\secrets.ps1` — файл с ключом DaData:
   ```powershell
   $dadataKey = "ваш_ключ_от_dadata.ru"
   ```
3. `_config\keywords_manual.txt` — (опционально) ручные ключи

### Запуск

```powershell
.\НАСТРОЙКА.bat
```

### Шаг 1/5 — Excel → CSV

**Скрипт:** `_bin\excel_to_csv.ps1`
**Вход:** `counterparties.xlsx`
**Выход:** `_data\companies.csv` (формат `name|inn`)

**Что делает:**
- Читает Excel через COM-объект
- Автоопределяет столбцы по заголовкам или по содержимому
- Проверяет, что ИНН — 10 или 12 цифр
- Убирает кавычки из названий (чтобы CSV не ломался)
- Использует pipe (`|`) вместо запятой как разделитель

### Шаг 2/5 — DaData Enrichment

**Скрипт:** `_bin\enrich.ps1`
**Вход:** `_data\companies.csv`
**Выход:** `_data\keywords_auto.csv` (~870 H-ключей)

**Что делает:**
- Для каждого ИНН запрашивает `findById/party`
- Извлекает: полное название, краткое название, ФИО директора
- Все данные пишет как **H-ключи**
- Использует кэш `dadata_cache.json` — при повторных запусках не тратит лимит API

**Лимит DaData (free tier):** 10 000 запросов в день.

### Шаг 3/5 — DaData Affiliated

**Скрипт:** `_bin\enrich2.ps1`
**Вход:** `_data\companies_raw.json`
**Выход:** `_data\keywords_checko.csv` (~278 M-ключей)

**Что делает:**
- По директору каждой компании ищет **все его другие фирмы** через `findAffiliated/party`
- По адресу ищет соседей через `suggest/party`
- Всё пишет как **M-ключи**

### Шаг 4/5 — Expand Names

**Скрипт:** `_bin\expand_keywords.ps1`
**Вход:** `_data\keywords_auto.csv`
**Выход:** тот же файл, перезаписанный (+350 H-ключей)

**Что делает — самое важное:**

DaData пишет названия как `ООО "ТИТАНОФФ"` — в новостях так не пишут. Скрипт извлекает **чистые названия**:

| Было | Стало |
|---|---|
| `ООО "ТИТАНОФФ"` | `ТИТАНОФФ` |
| `ОБЩЕСТВО С ОГРАНИЧЕННОЙ ОТВЕТСТВЕННОСТЬЮ "ГИПЕРГЛОБУС"` | `ГИПЕРГЛОБУС` |
| `ПАО "МЕГАФОН"` | `МЕГАФОН` |

**Стоп-лист** отсеивает слишком общие слова:
```
РЕГИОН, ПРЕМЬЕР, ИНВЕСТ, СТАНДАРТ, МИР, АВАНГАРД,
ФЛАГМАН, АРСЕНАЛ, ЭКСПРЕСС, ПАРТНЁР, КОД, ИСТОК ...
```

Без стоп-листа ключ `РЕГИОН` поймал бы **все** новости со словами «в российском регионе».

### Шаг 5/5 — Merge

**Скрипт:** `_bin\merge_keywords.ps1`
**Вход:** 4 файла
**Выход:** `_data\keywords_all.csv` (~2200 ключей)

**Что делает:**
- Читает все 4 источника:
  - `keywords_auto.csv` — H
  - `keywords_checko.csv` — M
  - `keywords_checko_fsrar_clean.csv` — L
  - `keywords_manual.txt` — ручные
- Дедуплицирует по строчным буквам
- При дубликате оставляет **наивысший приоритет** (H > M > L)
- Сортирует и записывает

**Формат выходного файла:**
```
H,ТИТАНОФФ
H,ГИПЕРГЛОБУС
H,Бредний Диана
M,Екатеринбург
M,оптовая торговля алкоголем
L,ПРОДРЕСУРС
L,ПОСТАВЩИК
```

## Режим 2: ЗАПУСТИТЬ

Запускается **ежедневно или раз в неделю**. Занимает 1–2 минуты.

```text
[keywords_all.csv] → [41 источник] → [Regex] → [Dedup] → [3 отчёта]
```

### Предварительные требования

1. Пройден режим 1 (`keywords_all.csv` существует)
2. Есть интернет

### Запуск

```powershell
.\ЗАПУСТИТЬ.bat
```

### Что происходит

**Шаг 1. Загрузка ключей.** Читает `keywords_all.csv` → ~2200 ключей.

**Шаг 2. Компиляция Regex.** Вместо 2200 вызовов `.Contains()` — один скомпилированный regex:

```powershell
$pattern = "ТИТАНОФФ|ГИПЕРГЛОБУС|Екатеринбург|..."
$kwRegex = [regex]::new($pattern, 'IgnoreCase')
```

Для коротких ключей (≤8 символов) добавляются **границы слов**:
```
(?<![А-Яа-я])МИР(?![А-Яа-я])
```

Так `МИР` не поймает `СМИРНОВ`.

**Шаг 3. Обход 41 источника:**

| Категория | Кол-во | Метод |
|---|---|---|
| Федеральные RSS | 19 | XML парсинг |
| BezFormata регионы | 12 | HTML парсинг |
| Отраслевые RSS | 10 | XML парсинг |

Между запросами к BezFormata — пауза 1.5 сек, чтобы не получить rate limit.

**Шаг 4. Matching.** На каждую новость:
```powershell
$fullText = "$title $description"
$matched = $kwRegex.Matches($fullText)
```

Если найдено совпадение → определяется наивысший приоритет.

**Шаг 5. Дедупликация.** Проверка по `seen_urls.txt`. Если URL уже в кэше — новость пропускается.

**Шаг 6. Запись отчётов** в `_results\`.

## Режим 3: ОБНОВИТЬ_ФСРАР

Запускается **раз в 2–3 месяца**. Обновляет L-ключи через анализ адресов из государственного реестра.

### Что такое ФСРАР

**ФСРАР** = Федеральная служба по регулированию алкогольного рынка. Публикует **открытые данные** — полный реестр лицензий на алкоголь/табак (1.67 млн записей). Формат — XML, 10 ГБ в распакованном виде.

### Запуск

```powershell
.\ОБНОВИТЬ_ФСРАР.bat
```

### 5 шагов

**Шаг 1. Скачивание** (`fsrar_opendata.ps1`)
Скачивает ZIP ~300 МБ с `fsrar.gov.ru/opendata/7710747640-reestrlic`.

**Шаг 2. Распаковка** (`fsrar_unpack.ps1`)
Распаковывает в XML 10.5 ГБ.

**Шаг 3. Стриминг-парсер** (`fsrar_parse.ps1`)

**Ключевая техническая фишка.** Файл 10 ГБ нельзя загрузить через `[xml]` — съест ~50 ГБ RAM.

Читаем **по 8 МБ чанками** через `StreamReader`:
```powershell
while (($read = $reader.Read($buffer, 0, $chunkSize)) -gt 0) {
    $chunk = $pending + [string]::new($buffer, 0, $read)
    $parts = $chunk -split '</row>'
    # парсим каждую <row>
}
```

**Результат:** 1.67M записей → `fsrar_all.csv` (790 МБ) за 14 минут.

**Шаг 4. Матчинг** (`fsrar_match.ps1`)
Два прохода:
1. Находит ваши компании в ФСРАР по ИНН
2. Собирает адреса филиалов (нормализует `ул.` → `ул`, `ё` → `е`)
3. Ищет другие компании по тем же адресам — «соседи по зданию»

**Шаг 5. Очистка** (`fsrar_clean.ps1`)
Убирает ИНН-строки и короткие огрызки.

**Результат:** `keywords_checko_fsrar_clean.csv` (~1148 L-ключей).

**Далее:** запустите `НАСТРОЙКА.bat` → новый файл подключится в Merge.

## Ключевые инженерные решения

### 1. Regex вместо `.Contains()`

**Проблема:** 2200 ключей × 500 новостей × 41 источник = 45M проверок.
**Решение:** один скомпилированный regex.
**Ускорение:** ×40.

### 2. Word boundaries для коротких ключей

**Проблема:** `МИР` ловит `СМИРНОВ`, `МИРОВОЙ`.
**Решение:** `(?<![А-Яа-я])МИР(?![А-Яа-я])` для ключей ≤8 символов.

### 3. Стоп-лист общих слов

**Проблема:** `РЕГИОН` ловит «в российском регионе» (сотни новостей).
**Решение:** стоп-лист в `expand_keywords.ps1` — 40+ запрещённых слов.

### 4. Clean names extraction

**Проблема:** `ООО "ТИТАНОФФ"` не встречается в новостях.
**Решение:** извлечение `ТИТАНОФФ` из юридической формы.
**Эффект:** нашли Шрёдера через Kommersant.

### 5. Стриминг XML

**Проблема:** 10 ГБ XML → `[xml]$content` съедает 50 ГБ RAM.
**Решение:** `StreamReader` с чанками по 8 МБ.
**Эффект:** 1.67M записей за 14 минут при 200 МБ RAM.

### 6. Кэш URL

**Проблема:** одна новость приходит из 10 источников.
**Решение:** `seen_urls.txt` — хэш-set всех обработанных URL.
**Эффект:** каждая новость показывается один раз между запусками.

### 7. Приоритеты H/M/L

**Проблема:** в отчёте каша из релевантных и мусорных новостей.
**Решение:** три раздельных файла.
**Эффект:** `results_high.txt` — только важное, читается за 2 минуты.

### 8. Кэш DaData

**Проблема:** лимит API 10 000 запросов в день.
**Решение:** `dadata_cache.json` — при повторных запусках берёт из кэша.
**Эффект:** после первого запуска — 0 запросов к API.

| Файл | Содержимое | Кому |

## Troubleshooting

### «0 находок в `results_high.txt`»

**Это нормально.** Компании небольшие, о них пишут редко. За неделю может не быть ни одной новости.

**Что проверить:**
- Совпадают ли реальные новости с ключами? Откройте `keywords_all.csv`, поищите чистые названия (`ТИТАНОФФ`).
- Работают ли источники? Откройте `sources_log.txt`.

### «Ошибка `The process cannot access the file`»

Файл `keywords_all.csv` открыт в Блокноте или Excel. Закройте его и запустите `НАСТРОЙКА.bat` заново.

### «Кракозябры в консоли»

`.bat` файл сохранён в неправильной кодировке. Пересохраните в **UTF-8 без BOM** или замените русские строки на латиницу.

### «DaData API key is empty»

Откройте `_bin\secrets.ps1`, вставьте реальный ключ из [dadata.ru](https://dadata.ru/api/).

### «BezFormata timeout»

BezFormata иногда отдаёт rate limit. Увеличьте паузу между регионами в `parser.ps1` (сейчас 1500 мс).
